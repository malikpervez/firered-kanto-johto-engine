## Expansion mechanics and fidelity limits

This is FireRed campaign content running on the fork's Expansion engine. The selected source contains material departures from original FireRed defaults:

- `include/config/general.h:54–59` identifies the RHH battle/Pokémon/item Expansion lineage; `73` sets `GEN_LATEST` to Gen 9; `76–77` enable the Expansion intro and replacement RNG. [General configuration](https://github.com/PokemonHnS-Development/pokehns-expansion/blob/167aa6d537b109bb229c231ddce4616974c4da71/include/config/general.h#L54).
- `include/config/pokemon.h:5–14` selects updated species types/stats/abilities/EVs/experience yields and Gen 7 level-up learnsets. `include/config/battle.h:5–16` mixes newer critical-hit chance, capture experience and shared experience with Gen 3 critical-hit multiplier. [Species configuration](https://github.com/PokemonHnS-Development/pokehns-expansion/blob/167aa6d537b109bb229c231ddce4616974c4da71/include/config/pokemon.h#L5), [battle configuration](https://github.com/PokemonHnS-Development/pokehns-expansion/blob/167aa6d537b109bb229c231ddce4616974c4da71/include/config/battle.h#L5).
- `include/config/overworld.h:5`, `15`, `28–33` select running indoors and newer NPC/PC behaviors. [Overworld configuration](https://github.com/PokemonHnS-Development/pokehns-expansion/blob/167aa6d537b109bb229c231ddce4616974c4da71/include/config/overworld.h#L5).
- `src/new_game.c:117–150` contains shared challenge defaults such as auto-run, modern moves, Fairy types and reusable TMs. However, `238–239` restores previously selected challenge settings immediately after applying defaults. This audit does not establish which values the FireRed new-game UI actually supplies. Record the effective runtime choices; do not import the HnS test's choices as FireRed evidence. [Challenge initialization](https://github.com/PokemonHnS-Development/pokehns-expansion/blob/167aa6d537b109bb229c231ddce4616974c4da71/src/new_game.c#L117).
- `include/config/debug.h:5–15` enables R+Start overworld and Select battle/summary debug entry points in source. Ordinary acceptance gameplay must avoid them. [Debug configuration](https://github.com/PokemonHnS-Development/pokehns-expansion/blob/167aa6d537b109bb229c231ddce4616974c4da71/include/config/debug.h#L5).

These are static configuration observations, not an exhaustive fidelity inventory or owner acceptance of deviations. No claim is made about stock-ROM equivalence, original-save compatibility, every Kanto gym, League progression or full Sevii content. Those require later separately authorized qualification.

A subsequent read-only save-reservation audit identified a concrete existing fidelity mismatch: `data/maps/OneIsland_PokemonCenter_1F_Frlg/scripts.inc:280` calls `InitRoamer`, but `src/roamer.c:122–163` selects Hoenn route tables for non-HnS targets and `357–363` initializes Latias/Latios. It has no FireRed-specific legendary-beast selection in that branch. This is VERIFIED IN SOURCE; the postgame trigger and resulting runtime behavior are NOT RUN. The target-separation patches leave this code untouched. See `docs/firered-repair-report.md` and the ignored roamer audit for exact evidence.

## Existing day/night support — source and limited palette observation

The owner's proposed FireRed day/night enhancement has existing shared-engine support to evaluate. At this pin, `include/config/overworld.h:93–103` already sets `OW_TIMES_OF_DAY=GEN_LATEST`, enables time-dependent encounter support and sets `OW_ENABLE_DNS=TRUE`. These definitions have no FireRed exclusion. The pinned configuration therefore requests day/night support for the FireRed target; this is not a claim that it works in a playable build. [Time and lighting configuration](https://github.com/PokemonHnS-Development/pokehns-expansion/blob/167aa6d537b109bb229c231ddce4616974c4da71/include/config/overworld.h#L93).

The source paths are concrete: `src/rtc.c:317–320` derives local time from the RTC and saved offset; `src/overworld.c:1719–1783` defines the morning/day/evening/night palette blends and calculates them from that time. `1815–1821` applies natural lighting to town, city, route and ocean-route map types, without an `IS_HNS` restriction. Pallet is `MAP_TYPE_TOWN` in `data/maps/PalletTown_Frlg/map.json:11`. `src/field_weather.c:794–806` selects the time-aware fade for naturally lit maps; `src/palette.c:906` implements palette mixing; `src/overworld.c:1897–1912` refreshes time blending during normal overworld updates. [Local time](https://github.com/PokemonHnS-Development/pokehns-expansion/blob/167aa6d537b109bb229c231ddce4616974c4da71/src/rtc.c#L317), [blending and map eligibility](https://github.com/PokemonHnS-Development/pokehns-expansion/blob/167aa6d537b109bb229c231ddce4616974c4da71/src/overworld.c#L1719), [weather fade](https://github.com/PokemonHnS-Development/pokehns-expansion/blob/167aa6d537b109bb229c231ddce4616974c4da71/src/field_weather.c#L794), [palette mixer](https://github.com/PokemonHnS-Development/pokehns-expansion/blob/167aa6d537b109bb229c231ddce4616974c4da71/src/palette.c#L906).

The active source schedule (`include/constants/rtc.h:83–97`) is morning 06:00–10:00, day 10:00–18:00, evening 18:00–19:00 and night 19:00–06:00. HnS's day/night outdoor-Pokémon visibility flag updates are inside a runtime `if (IS_HNS)` at pristine `src/overworld.c:1785–1800`. That still parses absent flags for FireRed; patch 0003 adds a preprocessor boundary around the existing block. Shared visual tinting does not establish that those Johto object rules apply to FireRed. Time-specific encounters also need appropriate content: `src/wild_encounter.c:417–451` selects time tables and falls back when a table is absent. An enabled switch alone does not prove distinct FireRed night encounters. [Schedule](https://github.com/PokemonHnS-Development/pokehns-expansion/blob/167aa6d537b109bb229c231ddce4616974c4da71/include/constants/rtc.h#L83), [encounter fallback](https://github.com/PokemonHnS-Development/pokehns-expansion/blob/167aa6d537b109bb229c231ddce4616974c4da71/src/wild_encounter.c#L417).

A blue nighttime outdoor palette was observed during the fresh 010 Pallet opening. Effective clock initialization, emulator RTC detection, time transitions, encounter changes and long-term persistence remain unverified. Although `OW_USE_FAKE_RTC` is `FALSE` in configuration, `include/fake_rtc.h:7–14` also consults the saved challenge RTC choice. `src/rtc.c:142–149` selects the fake RTC, a dummy date on RTC error, or hardware/emulator RTC input. The effective FireRed clock choice, emulator RTC detection, exterior/interior palette behavior and time persistence need evidence from the repaired ROM. No day/night feature, encounter table, clock setting or save-layout change was implemented by this review.
